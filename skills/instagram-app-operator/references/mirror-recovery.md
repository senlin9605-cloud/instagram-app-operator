# Device switching and connection recovery

Use for multiple physical iPhones or an unstable mirror. Device names and handles belong in the user's local map.

## Switch a physical iPhone

1. Read current device/account and preserve unfinished work through the supported draft action when needed. Do not publish just to clear a composer.
2. Quit iPhone Mirroring using its observed macOS menu. A shortcut may be forwarded to the phone; verify the application exits.
3. In System Settings → Desktop & Dock → Widgets, inspect the iPhone selector. Select the mapped device by name and verify the value. Use current UI labels if they differ.
4. Relaunch `com.apple.ScreenContinuity`, read the connected model/name and verify the Instagram handle. A changed preference is not proof that the live mirror switched.
5. If still connected to the previous device, recheck the preference and do one deliberate quit/relaunch. Stop if it still disagrees. Do not reset access or change networking as a shortcut.

Reuse the user's routine-switching authorization under the active host policy; do not ask again solely because a harmless preference selector is in System Settings.

## Reconnect

- For a visible interruption, use the observed Retry control when authorized. Re-observe until the phone or actual error is visible.
- Verify the handle and pending action after recovery. The last tap may have reached the phone; do not blindly replay sends, likes or publishing.
- With standing reconnect authorization, recover occasional later interruptions too. After two consecutive attempts fail to restore a usable screen, stop and report the blocker. A successful operation resets the recovery count. This is a reliability bound, not an activity limit.
- For phone-in-use errors, try the offered connection once; if it persists, ask the user to lock the phone. Hand off physical authentication/approval. Do not prescribe unlocking when mirroring requires a locked phone.
- Do not change VPN, Bluetooth, Wi-Fi, permissions or authentication to repair a routine interruption without the applicable authorization.

## Stable UI and exact input

- Use vision for the phone canvas and AX labels for macOS menus/windows.
- A fresh frame may still show animation, an earlier scroll position or placeholders. Observe again when there is concrete evidence of transition before choosing coordinates. Do not invent offsets or sleeps.
- After a miss, confirm the actual page before retrying. A tap returning OK does not prove navigation or submission.
- Verify full captions/comments. If input drops characters, use the sibling skill's input diagnosis; do not substitute a different meaning to work around typing. Inspect uncertain submissions before correcting them to avoid duplicates.

Official reference: [Apple iPhone Mirroring](https://support.apple.com/en-us/120421). Current runtime documentation and UI take precedence over historical observations.
